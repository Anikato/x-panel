# X-Panel UI 与主题系统规范

版本：1.3.3  
日期：2026-09-12  

1.3.3 修订：字段契约补全旧 overlay 字段、主题继承顺序、v1 公式与安全回退、资源输入边界、恢复组路径和解析验收用例。C.2 经复核：elevated/sidebar 不得塌成 surface/bg；ANSI 跟当前 bg/text；浅色亮色向黑混；图表安全序列仅为筛查。公开 schema 仍未冻结。详见 `theme-field-contract.md`。
状态：长期设计与开发约束；不表示所述能力已全部实现。公开 schema 在字段表与两个示例包闭合、且未经解析器兼容验证前**不得冻结**。字段契约见 `docs/theme-field-contract.md`。

### 1.2 相对 1.1 的契约变化

- 主题不再只能是仓库内写死的 `atelier` / `lumen`。内置主题仍是官方预设；用户可安装、导出、分享声明式主题包。
- 导入/导出不再是「后续」：必须同时支持 **主题包**（给别人用）和 **外观 overlay**（自己的微调）。现有 `x-panel.appearance` 属于后者。
- 全站表面必须走四种配方（page / card / inset / float），业务页不得再为列表行、下拉、弹层各写一套底色。
- 主色、副色是品牌色；成功/警告/危险/信息只表示状态，不得当装饰底。
- 自定义字体（本地上传 woff2/ttf/otf）必须支持，规则与背景图同类：限格式、限大小、不执行脚本；导出默认不携带字体二进制。
- 编辑器底色与透明度跟随终端；语法高亮仍用独立深浅主题，切换时不得销毁会话或丢失撤销栈。
- 设置页采用「和谐层 / 高级层」：默认只暴露会级联的少数旋钮；高级层才打开逐项覆盖，并提示可能破坏对比度。
- 后续细化选项必须可加性扩展：只增加可选字段和缺省派生，不改已有 key 含义，不要求旧主题包重写，不推翻表面配方。
- 主题**文件**允许省略字段；**运行时**由统一解析器补齐。不得把当前 TypeScript `ThemeDefinition` 直接当作公开 JSON 契约。
- 每个属性只有一条权威路径。高级显式覆盖 > 和谐层派生 > 主题包缺省 > 内置回退；无障碍/环境降级最后生效。改主色不清除用户写过的副色；恢复默认是删除覆盖字段。
- 四种配方的语义与消费者固定。hover / selected / disabled / wash / 顶边 / 材质是配方的参数或状态，不新增业务页配方。
- 抽屉外壳用 card；对话框与菜单外壳用 float；其中列表项用 inset。遮罩独立。背景 alpha 只合成一次。装饰配方不得引入模糊；材质模糊仅用于侧栏和顶栏。
- 两类文件使用整数 `schemaVersion` 与可选 `schemaMinor`。支持的主版本内，不得因更高的 `schemaMinor` 拒绝。现有外观 `schemaVersion: 1` 必须可读。检查 `schemaVersion === 1` 在只支持主版本 1 时是正确的。
- 缺失主题只做运行时回退，必须保留原 `themeId` 与其 overlay。未知字段产生可定位警告；同一主版本再导出应尽量保留未识别声明，若做有损降级必须提示。
- 缺省派生算法在同一兼容代内保持稳定；更换算法用可选策略版本，缺字段仍走原策略。
- 系统字体与 webfont 以**访问者浏览器**为准，不是面板主机的 Debian 环境。上传字体用受限二进制存储，不复用背景图的 JPEG/localStorage 方案。

## 1. 目的与适用范围

目标：美观、统一、合理、优雅，适合长期、高频运维使用；后续功能直接依据本规范接入。

适用于所有前端页面、公共组件、导航、浮层、图表、终端、编辑器和外观设置。保持单节点自治、单用户定位，采用侧栏、顶栏和内容区；桌面优先，默认深色，浅色同等完善。不引入 NAS 自由窗口系统。

本文是 UI 与主题设计的权威规范。早期 `2026-09-08-ui-upgrade-guide.md` 是阶段性迁移背景，其中现状描述可能已经过时；主题范围、页面结构与本文冲突时以本文为准。本文不改变后端职责或发布流程。

术语：**必须**是验收要求；**建议**允许说明理由后采用替代方案；**可选**不要求立即实现。新增功能必须遵守；存量页面按模块迁移，不要求一次重写全站。文档约束不能替代实际代码和视觉检查。

## 2. 主题的定义与不变边界

主题是完整、协调且经过验证的外观配置预设。它同时覆盖风格、明暗配色、密度、字体、图标、材质、区域外观和动效。用户可以在预设上覆盖部分配置。

主题可改变视觉表现，不得改变功能归属、菜单顺序、权限、数据、表单字段顺序、操作语义、快捷键和保存行为。侧栏可改变宽度与外观，不能因换主题而把某功能移入其他模块。页面内容布局由页面模板负责；首页模块重排是独立产品能力，不属于主题。

主题可配置项目不等于设置页必须暴露所有参数。标准定义能力边界，正式主题提供可靠搭配，普通用户只需选择预设。

## 3. 信息架构与页面规范

### 3.1 导航语义

| 类型 | 用途 | 规则 |
| --- | --- | --- |
| 全局导航 | 选择模块，如文件、网站、容器 | 主侧栏；优先沿用现有导航注册表，禁止页面另建全局菜单 |
| 模块导航 | 同一模块的不同任务或资源 | 横向或侧向导航，由模块稳定选择 |
| 对象导航 | 某网站、容器等对象内的配置分区 | 对象标题之后显示，明确对象上下文 |
| 视图控制 | 筛选、排序、列表/网格切换 | 放内容工具栏，不能伪装成新层级菜单 |
| 页内目录 | 滚动到内容位置 | 明确目录外观与当前位置，不能与切换页面的菜单混淆 |

少量、短标题的同级任务适合横向导航；较多或需要分组的项目适合侧向导航。不能机械地以某个数量阈值切换，也不能仅因窗口变窄改变导航语义。不得堆叠两排外观相同的选项卡。较深结构优先通过分组、详情页和内容标题简化，不能不断追加横向标签。

### 3.2 固定页面顺序

面包屑（需要时）→ 页面或对象标题、状态、页面操作 → 模块或对象导航 → 当前分区工具栏 → 正文 → 分页或表单操作区。

每个内容上下文只保留一个主标题。全局顶栏不重复页面标题。页面操作与当前分区操作分开：对象启停属于对象操作，新增某条规则属于当前分区。主要操作清楚，次要操作克制，危险操作不得抢占默认视觉焦点。

公共外壳与页面必须明确标题、导航、工具栏的所有权，避免外壳导航在标题上方、另一页面又在标题下方。迁移期间可兼容旧页面；最终不得依赖 CSS 隐藏旧导航维持两套结构。

### 3.3 页面模板

| 模板 | 基本结构 | 典型用途 |
| --- | --- | --- |
| 列表 | 标题、导航（可选）、筛选与操作、列表、分页 | 网站、证书、备份记录 |
| 对象详情 | 返回与上下文、对象标题/状态、对象导航、分区内容 | 网站配置、容器详情 |
| 设置 | 标题、分类导航、单分类内容、保存反馈 | 面板设置、大量配置项 |
| 工作台 | 紧凑标题/工具栏、占满可用空间的工作区 | 文件、终端、编辑器 |
| 监控 | 标题、时间与筛选、指标、图表、明细 | 主机监控、流量 |

工作台不强制卡片包裹，不强制固定表单宽度。设置类优先分类切换；保留长页目录时必须明确目录语义。表单内容可以限制阅读宽度，表格和工作台利用可用宽度。

列表页禁止用卡片包裹整张表。筛选与页面操作放进工具栏（`.app-toolbar` / `.filter-bar`）。状态、用量等摘要用 deck / metric 表面（与首页同一配方），不要 `el-card` 套进度条。分区标题（如磁盘的块设备）用 `.xp-section`，不得再充当页主标题。表单、对话框、表格控件可继续用 Element Plus。

网站详情建议按基本信息、访问与路由、HTTPS、安全与性能、日志与诊断、高级配置分组。分组内用标题和表单区段，避免再次堆叠完整标签栏；迁移必须保留全部已有功能和直达路径。

### 3.4 新功能归属

新增前先判断能否归入现有模块，再选择页面模板与局部导航。不得使用“其他”“工具箱”作为长期兜底；不得仅因某技术组件独立即增加一级入口。确有新模块时，说明用户任务、与现有模块的边界及入口位置，并更新导航注册与本规范。

## 4. 主题能力矩阵

以下为必须预留的主题表达范围，不代表首期需要实现所有变体。参数集中声明，业务页面不得逐页解释主题名称。

| 类别 | 可配置项目 | 边界与回退 |
| --- | --- | --- |
| 配色 | 强调色、文字主次、链接、边框、选中、成功/警告/错误/信息 | 使用语义色；状态同时有文字或图标 |
| 页面背景 | 纯色、受控渐变、背景图、遮罩、位置与缩放 | 默认纯色；图片失败回退底色；不允许影响交互 |
| 材质 | 区域不透明度、背景模糊、色调叠加 | 分别作用侧栏、顶栏、表面、浮层；正文文字不随父容器透明 |
| 表面 | 基础、嵌套、浮起、悬停、选中、遮罩 | 表面层级有语义；避免卡片套卡片 |
| 字体 | 界面与等宽字体、字号梯度、字重、行高、字距、系统栈、可选 webfont、用户上传字体 | 完整中文回退；数字指标稳定；字体失败不阻塞页面；上传字体不得执行脚本 |
| 图标 | 套系、描边/填充、粗细、尺寸、光学对齐、容器形状与背景 | 同一语义映射；缺失回退统一套系；不得依赖外网图标请求 |
| 密度 | 页面边距、区块间距、控件高度、行高、单元格留白 | 选择协调预设；字号变化不得裁切文字 |
| 形状 | 控件、标签、导航项、卡片、浮层圆角 | 同一圆角预设贯通公共外壳与控件；禁止侧栏选中、顶栏芯片、Logo 另写一套半径 |
| 边框 | 普通、弱化、强调、交互、分隔线的颜色与粗细 | 焦点与输入边界可辨 |
| 阴影 | 卡片、悬停、菜单、抽屉、弹窗 | 有限层级，不对所有元素加阴影 |
| 侧栏 | 宽度预设、背景材质、分组文字、项目高度、图标间距、分隔、选中标记 | 支持标记线/色块；色块选中跟随控件圆角，不得做成不受圆角风格约束的大胶囊 |
| 顶栏 | 高度预设、背景材质、底边、工具按钮外观 | 主机名芯片、搜索入口、工具按钮跟随控件圆角；头像可保持正圆 |
| 子导航 | 线式、块式、胶囊式、侧向项目外观 | 只出现在模块/对象导航，不出现在设置分类；胶囊是唯一允许全圆的导航变体；变体不改变横向/侧向的模块选择 |
| 卡片 | 平面/描边/轻浮起、内边距、标题区、图标底座、交互反馈 | 信息与操作位置保持模板一致；不可点击卡片不伪装可点击 |
| 按钮 | 主次填充、边框、文字、尺寸、圆角、加载与按压反馈 | 主次与危险语义固定；完整禁用状态 |
| 输入控件 | 输入框、选择器、复选、单选、开关、滑块的表面与状态 | 保留组件标准键盘行为；不得只靠颜色表达选中 |
| 表格/列表 | 表头、行分隔、斑马纹、悬停、选中、密度、展开区 | 不改变字段顺序；横向溢出有明确处理 |
| 标签/反馈 | 状态标签、告警、提示、通知、空/错误/加载状态 | 全部主题覆盖，长文案可读 |
| 弹窗/抽屉 | 遮罩、表面、阴影、圆角、内间距、转场 | 焦点管理、关闭行为与业务不变 |
| 图表 | 分类与连续色板、网格、轴文字、线宽、区域填充、提示框 | 多序列可区分；切换外观不得重置查询 |
| 终端 | ANSI 色板、背景、字体、行高、光标、选区、背景透明度、跟随面板背景、本机/网络图片 | 终端页、快速终端、容器终端共用同一套终端外观；改透明度和背景立即作用于已打开会话；不重建会话。透明度作用在终端配色与背景之间，不透视面板。默认跟随面板星空或图片 |
| 编辑器 | 语法配色、行号、选区、当前行、光标、字体；工作区背景与透明度跟随终端 | 保留内容、撤销栈、滚动位置；不因换主题重建编辑器 |
| 动效 | 时长、缓动、淡入、位移、缩放、悬停、展开、加载反馈 | 不阻塞输入；减少动效优先；禁用无限装饰动画 |
| 细节 | 滚动条、分隔符、骨架屏、工具提示、焦点环 | 原生兼容与可访问性优先 |

Logo 与产品名称属于品牌配置，不因切换普通主题而悄悄改变。背景图可以属于主题资源。面板提供静态共享背景（丝带 / 银河 / 星空，纯 CSS、无动画）与一张可选背景图；侧栏、顶栏、卡片、弹窗、抽屉透过透明材质看到同一层，不分别配置。

## 5. 参数、语义与组件变体

采用 **色板 → 语义变量 → 表面配方 → 公共组件** 的关系。颜色值、阴影等集中定义；页面只使用语义名，不写主题 ID，不写页面专属色。

色角色必须固定：

| 角色 | 语义名（逻辑） | 用途 | 禁止 |
| --- | --- | --- | --- |
| 主色 | accent | 主按钮、选中、进度、卡片顶边细线 | 不当每一张子卡的底 |
| 副色 | accent-secondary | 次要强调、双指标对比（如下行/内存） | 不每张卡换一种副色 |
| 填充 | fill-1 / fill-2 | 所有 inset 子卡、表格行、会话项的底与悬停 | 不借用 info/success 当填充 |
| 状态 | success / warning / danger / info | 只表示对错与告警 | 不当装饰主色 |

表面必须只有四种配方，换主题只换配方内容。配方的**消费者归属**固定：

| 配方 | 外壳用在哪 | 内部列表项 |
| --- | --- | --- |
| page | 主内容后的面板背景（纯色、丝带/银河/星空、可选图） | — |
| card | 大卡片、列表容器、**抽屉外壳** | 抽屉内的任务行等用 inset |
| inset | 网络/系统子卡、证书行、数据库行、任务行、终端会话项、表格行 | 自身即行 |
| float | 下拉、气泡、主机名状态、文件「更多」、**对话框/MessageBox 外壳**、提示框 | 菜单项用 inset 的 selected/hover 状态 |

每种配方必须定义这些状态，缺省由 fill-1/fill-2 与边框派生，以后加「hover 强度」只调参数：

| 状态 | 含义 |
| --- | --- |
| default | 静止 |
| hover | 指针悬停 |
| selected | 当前行/选中项 |
| disabled | 不可用 |

合成顺序固定，避免各页私自叠加。图层分两类：

- **始终参与**：配方底、可选 wash、边框与顶边、状态叠层。  
- **条件替代**：不透明回退底（`--xp-bg-*-solid`）仅在禁用透明或运行环境降级时**替换**透明材质，不是永远垫在底下的一层。透明开启时不得先画实心底再往上掏空。

透明材质只作用于明确列出的背景图层：侧栏、顶栏、card/float 的配方底与 wash。**不作用于**正文、图标、焦点环、滚动条。alpha 只乘一次，禁止 elevated 已含 alpha 再乘区域 opacity。

状态组合由公共配方统一定义，消费者不得自行发明：

- `disabled` 抑制 hover，也不显示选中高亮的可交互反馈。  
- `selected + hover`：在 selected 底上叠加公共 hover 层，v1 的精确颜色和强度见字段契约 C.2，不由消费者选择。
- `disabled + selected`：保持 selected 的静态识别（如描边或低对比填充），无 hover。

边框与顶边：顶边是 **card 配方参数**。公开主题文件契约冻结之后，该参数缺省必须保持冻结时的行为。首次把业务卡迁入配方时允许有意改视觉（例如首页仪表卡已有顶边、部分旧 `el-card` 没有），这种收口列在第 14 节，**不得**为保留旧局部装饰增加页面专属字段。

**材质模糊**只允许用在侧栏和顶栏，且可被减少动效与「不支持模糊」关掉。**配方装饰禁止模糊。**

共享背景画在布局容器上。挂到 `body` 的浮层看到的是**实际下层画面**；若该浮层带遮罩，看到的是含遮罩的合成结果。浮层并非都有遮罩。不得为了「同一层」再复制一张背景图或再加一层 blur。

证书行、数据库行、任务行、终端列表项必须共用 inset，不得各做一套渐变。

可继续沿用现有 CSS 变量与 Element Plus 变量，通过集中适配层映射；不要同时建立重复主题体系。具体变量命名可在实施时统一，但必须提供完整字段清单、类型、默认值、单位、范围和消费者。

侧栏标记线与色块、局部导航线式/块式/胶囊、卡片平面与浮起等通过受控组件变体表达。每种变体由公共样式/组件实现；主题选择变体。侧栏色块不是胶囊；全圆只用于局部导航的胶囊变体。禁止按主题 ID 在各业务页面散布判断，禁止为每个主题复制页面。硬编码圆角（如 `8px`、`999px`）不得出现在公共外壳。

图标通过语义名称映射套系；品牌商标单独处理。图标替换不能改变含义。换字体后必须验证中文、英文、数字、长路径与等宽内容。

优先复用 Element Plus。只抽取实际复用的页面外壳、标题、导航、工具栏、设置分组和状态组件；不要求包装每一个基础按钮，不自建通用页面渲染引擎。

## 6. 推荐基线与值域

以下是首个专业中性主题的起点，不是其他主题必须照抄的审美，也不是已经通过视觉测试的结果。

| 项目 | 基线/值域 |
| --- | --- |
| 顶栏 | 默认 56px；支持 48/56/64px 预设 |
| 侧栏 | 默认 224px；支持 200/224/256px，折叠 64px |
| 页面边距 | 标准 24px，较窄桌面 16px；工作台可专门处理 |
| 间距梯度 | 4/8/12/16/24/32px |
| 字号 | 正文默认 14px，主标题 22–24px，区块标题 16px；用户缩放建议 0.9–1.2 |
| 密度 | 紧凑/标准/舒适；控件高度起点 32/36/40px，表格行高起点 36/44/52px，内容需要时可增高 |
| 圆角 | 默认控件 6px、卡片 10px、浮层 12px；用户预设方正/默认/圆润对应控件 2/6/10px。同一预设必须同时作用于侧栏项、顶栏芯片、Logo、图标底座、按钮、输入、卡片、浮层。唯一例外：局部导航「胶囊」变体使用全圆 |
| 区域不透明度 | 0–1 校验；正式主题通常 0.8–1；任意背景下仍须验证，值域不保证可读性 |
| 背景模糊 | 0–20px；默认关闭，降级为不透明表面 |
| 动效 | 悬停 80–120ms，页面 0–120ms，菜单 120–160ms，抽屉 160–200ms；常规反馈上限 240ms |
| 深色起点 | 页面 #111318，表面 #191C23，浮层 #222630，正文 #EEF0F4，次要文字 #A4ADBC |
| 浅色起点 | 页面 #F5F6F8，表面 #FFFFFF，正文 #1D2433，次要文字 #596579 |

主题允许提供协调的密度默认值，个人偏好可覆盖。不得分别随意缩小字体、行高、控件导致裁切。正文普通文字对比度验收目标至少 4.5:1，大号文字及必要非文本控件边界目标至少 3:1；需实测，不因采用基线颜色即声称达标。

## 7. 主题配置契约、文件与偏好

### 7.1 两种正式文件，不要混成一种

可借鉴的成熟方向：

| 系统 | 可借鉴 | 不照搬 |
| --- | --- | --- |
| VS Code | `kind` + schema 的 JSON 主题；工作区 `colorCustomizations` 是 overlay，不改主题文件本身 | 不引入扩展市场和 TextMate 语法作用域 |
| Catppuccin / Rosé Pine | 先定 10～15 个命名色，再派生表面和强调；换一组色板整套和谐 | 不把所有 ANSI/语法色一上来暴露给普通用户 |
| shadcn / Radix 色板 | `--background` `--card` `--popover` `--primary` `--muted` 这种短语义表，杠杆高 | 不把 React 组件约定带进本项目 |
| Home Assistant | 受约束 key 列表的 YAML/JSON 主题，缺 key 回退 | 不采用无 schema 的任意 CSS |
| Obsidian Style Settings | 主题作者声明哪些旋钮可调 | 不开放任意 CSS/JS 注入 |

X-Panel 采用 **色板优先 + 短语义表 + overlay**，对应两份文件：

| 文件 | `kind` | 给谁 | 装的是什么 |
| --- | --- | --- | --- |
| 主题包 | `x-panel.theme` | 作者 / 分享 | 完整主题：深浅色板、派生规则、默认密度字体变体、终端与图表映射 |
| 外观 overlay | `x-panel.appearance` | 用户 / 多台面板同步自己的微调 | 当前选用的主题 id、明暗、以及对该主题的覆盖项 |

已实现的导出属于 `x-panel.appearance`。它不能代替主题包：别人导入 overlay 只会套在自己已装主题上；没有主题包就无法分享「一整套皮肤」。

解析顺序保持：

**内置缺省 → 已安装主题包 → 当前明暗模式 → 用户 overlay → 无障碍与运行环境降级。**

全局模式仍为深色、浅色或跟随系统；首次安装默认深色。凡称为正式主题的包必须带齐深浅两套，或提供可确定解析为完整两套的继承。切换主题默认加载该包的完整预设；旧主题的 overlay 按主题 id 分存。跨主题只可选保留字号、密度、终端字体等 `CROSS_THEME_KEYS`。减少动效始终生效。界面显示「主题名 · 已自定义」。

必须支持按组和全部恢复默认。预览用草稿，应用后一次持久化。取消、关闭或预览失败恢复原配置。预览不得被持久化 watcher 误保存。失败必须提示。

外观 overlay 默认仍是当前浏览器本地偏好，并可备份到面板设置；跨设备静默覆盖禁止。主题包安装在该面板上。

联合导出保持两个 `kind`，不要发明第三套主题语义。若一次下载两份，使用规定容器（例如 zip 内各一份 JSON）或连续提供两个文件；overlay 引用的主题包缺失时必须提示依赖，**不得**把 themeId 静默改成 `atelier`。

### 7.2 主题包 schema（`x-panel.theme`）

主题包是声明式 JSON，UTF-8，无 JS、无内联 CSS 选择器、无绝对本机路径。

**文件格式**允许省略可由派生补齐的字段。**运行时定义**必须完整。二者由**同一个**解析器连接；不要第二套主题引擎。当前仓库里的 TypeScript `ThemeDefinition` 是迁移期运行时形状，**不是**公开文件契约。首次实现主题包前必须另列字段表：类型、单位、范围、缺省、消费者。

每个属性只有一个权威路径，禁止 `defaults.variants` 与顶层 `variants`、`derive` 与 `terminal/charts` 两处都能当最终值且规则不明。约定：

| 权威位置 | 管什么 |
| --- | --- |
| `palette` | 作者写下的色。hover、muted、onAccent、fill 仅为运行时派生结果，不是文件字段；可选背景及文字字段见字段表 |
| `derive.strategy` | 派生算法 id。缺省为 `v1`。更换混色公式必须换策略 id，旧包未写策略时永远走 `v1`。分享文件**不得**携带派生结果缓存。文件中若出现已识别的禁止字段（含任何派生结果缓存），导入与导出时**剥除并报告路径**，不得当未知声明原样保留 |
| `defaults` | 用户没覆盖时的密度、字体、纹理、透明、变体 |
| `variants` | 只出现在 `defaults` 下，不在顶层重复 |
| `surfaces` | 四种配方如何引用 palette 与 wash 强度；禁止 blur |
| `terminal` / `editor` / `charts` | 作者缺省。终端/图表缺失按字段契约 C.2 派生及校验；编辑器缺失选择 vs-dark/vs。用户主色覆盖对图表的作用见 C.2，副色不阻断图表计算 |

`palette` 深浅各一份，第一期 light 必须显式给出。必选为 bg、surface、text、textMuted、border、accent、success、warning、danger、info；elevated、inset、accentSecondary 及其他背景/文字细项可省略，按字段契约 C.2 派生。背景只接受不透明 #RRGGBB，透明由区域 opacity 唯一控制；边框可带 alpha。

| 字段 | 职责 |
| --- | --- |
| kind | 恒为 `x-panel.theme` |
| schemaVersion | 结构主版本，整数。现有 `1` 必须可读。只支持主版本 1 时，判断 `schemaVersion === 1` 是正确的。禁止因 `schemaMinor` 更高而拒绝，或升级后不再读取旧主版本 |
| schemaMinor | 可选，缺省 0。更大的次版本只增加可选字段 |
| id | 稳定 slug，`[a-z0-9][a-z0-9-]{1,63}`；与已装包冲突必须确认，不得静默覆盖官方 `atelier` / `lumen` |
| name / version | 显示名与**主题内容**版本，和 schemaVersion 独立 |
| palette | 见上 |
| derive | 可选，仅 `strategy`。禁止写入派生结果缓存 |
| defaults | 推荐 mode、density、uiFont、termFont、termBgOpacity、chromeTexture、transparency、variants |
| surfaces | 配方映射与 wash |
| terminal / editor / charts | 可选显式覆盖 |
| fonts | 系统族名、内置 key 或 `https:` webfont；禁止 `file:` 与 data URL 作为分享包默认内容 |
| assets | 可选 https 背景图 URL；禁止可执行脚本 |

作者应主要通过改 palette 和 defaults 出新主题。内置 `atelier`、`lumen` 必须能导出为该文件格式；省略字段经解析器补齐后，与运行时效果等价。不能靠短 palette 表达的权威差异（如 lumen 的 variants、transparency、区域 opacity、动效）必须显式出现在文件里，禁止靠主题 id 隐式补齐。

完整字段表与解析关系见 [`docs/theme-field-contract.md`](theme-field-contract.md)。示例包见 `frontend/src/theme/examples/`。

### 7.3 外观 overlay schema（`x-panel.appearance`）

沿用现有结构：`kind`、`schemaVersion`、`exportedAt`、`preference`（themeId、mode、reduceMotion、keepPersonalPrefsAcrossThemes、overridesByTheme）。现有 `schemaVersion: 1` 必须继续可读。主题包与外观 overlay 均可带可选 `schemaMinor`。

现有外观导出**已经**同时带外层 `schemaVersion` 与内层 `preference.schemaVersion`（见 `preset-file.ts`）。缺的是双层校验与迁移规则，不是外层字段。字段表规定：先校验外层主版本，再校验/迁移内层；当前支持组合仅为外层 1 + 内层 1。不得只校验其中一层。

导出必须剥掉：身份凭据、业务数据、绝对路径、`upload` 模式的背景图和字体二进制。允许保留 https 图/字体 URL。导入只接受声明式字段。主版本不支持则拒绝，保留原外观。安全剥离优先于无损往返。

未知字段与未知枚举：产生**可定位**警告，不得整包失败。未识别声明**隔离保存**，只用于再导出，**不得**并入运行时 CSS 变量，不得触发资源加载。用户按组恢复默认后，隔离袋里的旧值不得把已删除的覆盖填回来。若因安全剥离丢失字段，导出时报告具体路径。

未知 `derive.strategy`：运行时回退 `v1` 并警告，**持久化与再导出必须保留原策略 ID**，不得改写成 `v1` 还声称无损。

`themeId` 指向未安装的主题时：**运行时**可回退到 `atelier` 显示，但**持久化不得改写** `themeId`，也不得删除该 id 下的 overlay。先导入外观、后安装主题包时，微调必须还在。

### 7.4 和谐层：让用户能调，但不容易调乱

用户能动的部分尽量多，但设置页不得把全部 token 平铺成调色板。分两层：

**和谐层（默认看见）** — 每个旋钮必须级联多处，保证整套仍像同一个主题：

1. 选用主题包  
2. 明暗 / 跟随系统  
3. 主色（预设 + 自定义 hex）。每个派生结果**独立**看覆盖：显式副色只替代副色派生，**不阻断** hover、muted、图表首色、顶边等其它结果。改主色不得清除已有显式副色  
4. 表面家族（石墨/深渊/纯黑等，深浅都生效，同时改 page/card/inset/float）  
5. 面板背景纹理（无/丝带/银河/星空）与可选图  
6. 密度、圆角  
7. 界面字体、等宽/终端字体、终端透明度  
8. 材质总开关（透明开/关，再细到侧栏顶栏表面）

**高级层（折叠）** — 逐项覆盖：副色独立、变体、侧栏宽度、顶栏高度、终端是否跟随面板、编辑器语法主题、单侧 opacity。改高级项时显示「可能破坏对比度 / 与主题包不再一致」，并提供按组恢复。

禁止把「证书行颜色」「数据库行颜色」做成独立选项；它们属于 inset 配方。高级层只能覆盖**共享角色与配方参数**（例如副色 hex、inset hover 强度、card 顶边开关）。禁止任意 token 路径、组件名或页面级 CSS 变量覆盖，否则会绕回每页一种颜色。禁止页面级主题判断。

覆盖优先级（高 → 低）：

1. 无障碍与运行环境降级（减少动效、关闭模糊、强制不透明表面）  
2. 用户高级层显式覆盖  
3. 用户和谐层派生（由主色、表面家族等算出）  
4. 主题包 `defaults` / `palette` / `derive.strategy`  
5. 内置安全回退  

恢复某组默认 = 删除该组在字段表中列出的已知覆盖，以及隔离袋里路径前缀属于该组的未知项。无法归入任何组的隔离项只在「全部恢复」时清除。不是写入一份「等于默认」的值。布尔与数字缺省必须区分「字段缺失」与 `false` / `0`；实现不得用 `||` 把它们吞掉。

用户 overlay 的标量（主色、副色 hex、配方参数、字体、密度、圆角等）**跨深浅共用**。主题包 `palette` 深浅分列。将来若要分模式覆盖，只能**新增**可选 `overridesByTheme[id].byMode`，不得把已有标量改解释成对象。

### 7.5 字体三档

| 档 | 来源 | 环境 |
| --- | --- | --- |
| 系统栈 | `system` 必须包含 `Noto Sans CJK SC`、`Noto Sans`、`DejaVu Sans`、`Liberation Sans` 及通用回退 | 以**访问者浏览器**已安装字体为准。面板装在 Debian 13 上并不等于浏览器有这些字体 |
| 可选 webfont | 内置 key（至少 LXGW WenKai、Noto Sans SC、JetBrains Mono）经 https 加载 | 需**访问者浏览器**能访问该 CDN，并满足 CORS/CSP；失败回退系统栈并提示。不是「面板主机能访问 CDN」 |
| 用户上传 | woff2 / ttf / otf，`FontFace` 加载二进制 | 不依赖系统装包。单文件与总量设上限（实施时写死）。完整 CJK 往往超过 2MB，必须允许子集字体，界面中文回退到系统栈 |

上传字体使用**受限二进制存储**，不复用背景图那套「缩放成 JPEG data URL 再进 localStorage」。显示名与内部族名分开。必须有与背景图同类的草稿、取消、异步过期检查、保存失败回滚；取消预览要卸载 `FontFace`。导出不含字体二进制，只保留可移植回退声明（例如 `uiFont: system` 或 webfont URL）。缺失或损坏时回退 `system`，页面不得白屏。不得 `@import` 任意 CSS、不得加载 `.js` 字体包。

必须支持整组及整体恢复默认。外观默认是当前浏览器的本地偏好；跨设备同步不得静默覆盖另一台机器的字体文件。

### 7.6 可加性扩展（以后加细项不得推翻）

主题系统的第一期可以不暴露所有旋钮，但数据结构必须允许以后只「填字段」，而不是改架构。

| 规则 | 要求 |
| --- | --- |
| schema 版本 | 整数主版本 + 可选次版本。支持的主版本内不得因更高 `schemaMinor` 拒绝。`schemaVersion === 1` 在只支持主版本 1 时合法。主版本变化才允许改 key 含义或删字段，且必须带迁移器 |
| 未知字段 | 不得整包失败；记可定位警告。隔离保存、不解释、不加载资源。安全剥离优先；丢失时报告路径 |
| 缺省行为 | **公开主题文件契约冻结之后**，新字段缺省必须保持冻结时的视觉与行为。`false`/`0` 是有效值。更换混色/wash/ANSI 必须换 `derive.strategy`，未写策略的旧包继续用 `v1`。契约冻结**之前**的配方收口（例如给 card 加顶边）是有意视觉迁移，列在第 14 节，不为旧装饰加页面专属字段 |
| 新旋钮挂靠点 | 新选项必须归入已有色角色、表面配方、和谐层或高级层之一。禁止为「某一个业务页」新增主题 key |
| 枚举 | 官方枚举可增不可改义。无法识别的枚举值回退默认，不崩 |
| CSS | 只新增 `--xp-*` 变量；页面继续只消费语义名。不得为新选项复制一套 scoped 背景 |
| 内置主题 id | 主题 id 是经校验的 slug 字符串。新增主题**不得**修改 `ThemeId` 联合类型。`atelier` / `lumen` 只是两个预装包，由目录注册而不是类型联合冻结 |
| UI | 和谐层保持短。新的细项默认进高级层或「按组展开」；只有会级联全站的才升到和谐层 |

扩展验收（在配方收口之后）：增加「inset 悬停强度」「副色独立 hex」「卡片顶边开关」时，可以改可选字段、校验/sanitizer、派生、恢复分组、公共配方 CSS、设置项和测试，**不得要求再改已经收口的业务消费者**。必须验证：字段缺失、`0`、`false`、按组恢复、未知字段往返、旧文件导入。顶边等效果不得再写在某个业务页的 `box-shadow` 里。

「旧 JSON 能导入」只证明兼容读取，**不能**单独当作细项无痛扩展、分享无损或对比度达标的证据。

## 8. 配置校验、迁移与降级

新增字段必须有回退值；旧主题无需逐个修改也能显示新增公共组件。字段缺失按继承链补齐，非法值采用默认值并提示；不支持的结构主版本拒绝应用，保留原主题。

保留现有用户外观偏好，采用有版本、可重复执行的迁移。不得启动时无条件重置。配置损坏不能导致页面白屏；恢复到默认主题并提供重置入口。

主题包与外观 overlay 的导入/导出是必须能力，不是后续项。导出不包含身份凭据、业务数据、绝对本机路径或上传二进制。导入只接受受支持的声明式字段，不执行 JavaScript、不注入任意 CSS/HTML。资源格式与大小必须限制；缺失资源回退到基础背景、系统字体或默认图标。已装主题包与内置主题冲突时要求确认覆盖，不得静默替换官方 `atelier` / `lumen`。

禁用透明、设备不支持模糊或运行环境需要降级时，以专门的不透明表面变量替代；不能简单去掉背景造成穿透。操作系统减少动效设置优先，不移除必要的进度反馈。

## 9. 动效与运行时行为

使用明确的属性过渡，禁止 `transition: all`。优先 opacity/transform，避免大面积持续模糊与重排动画。页面切换不得人为先等待退场再加载新页面。展开内容确需尺寸动画时限制范围并检查布局成本。

应用主题不得刷新页面、重建终端、丢失表单、改变当前路由或重置表格查询。图表、编辑器通过自身主题接口更新；必须检查滚动位置、选区与会话保留。加载区尽量保留尺寸，减少跳动。

切换主题可以即时完成，不要求全屏动画。不能用动画掩盖请求等待；请求状态与视觉效果分别管理。

## 10. 外观设置的信息结构

1. 主题选择：内置包与已安装包的预览图、名称、深浅预览、一键应用；安装/删除用户主题包。
2. 和谐层：明暗、主色、表面家族、背景纹理、密度、圆角、字体、材质总开关。强调色用预设色板加独立自定义色，选中态不得用会压到相邻行的外扩光环。
3. 高级层：副色、图标与导航变体、分区域材质、终端跟随、编辑器语法主题。选项若只作用于部分页面，必须写明出现位置。
4. 导入/导出：分别提供「导出主题包」「导出我的外观」「导入」。导入时按 `kind` 分流；无法识别则拒绝并说明。

提供预览、应用、取消和恢复默认。整体材质强度应先于各区域覆盖；独立参数不全部平铺。改变会影响多处时用短说明解释，不把技术变量名直接展示给普通用户。

## 11. 实施顺序与存量迁移

### 阶段 A：公共基础与默认主题

盘点现有 appearance、主题样式、Element Plus 覆盖与导航注册；复用并收敛到单一来源。固化配置字段、解析与回退，完成默认主题深浅模式、公共页面结构和规范展示页。

### 阶段 B：样板与第二主题

以网站列表/详情、证书管理、面板设置验证不同深度；以文件或终端验证工作台。增加一种明显不同的主题，至少在图标、卡片/导航变体、材质或字体中体现真实差异。第二主题不得修改业务页面来适配。

### 阶段 C：逐模块推广

按高频文件、终端、网站、网络、容器、备份优先。每个模块记录已迁移范围及例外。迁移时清理重复标题、旧导航和局部硬编码；不得顺便改变业务逻辑。表面配方、色角色、主题包文件与自定义字体在阶段 C 内落地，不得再以「后续」推迟。

新增/实质修改的 UI 必须使用公共主题能力；未触及的旧页面不阻塞合并。必要例外必须在变更说明中记录具体位置、原因、影响和替代计划，不以“以后统一”作为无期限理由。

## 12. 规范展示页与验收

提供项目内开发用规范展示页，展示所有导航、按钮、表单、列表、卡片、浮层、状态与排版样例。可切换正式主题、深浅和密度；不必暴露为普通用户主菜单。

每次新增组件或变体，同步补充展示样例。每个正式主题发布前必须检查全部公共组件，不能只验证首页截图。

验收清单：

- [ ] 新功能归属明确，使用合适模板，无重复主标题和同形嵌套导航。
- [ ] 使用语义变量与图标映射，无新增页面专属主题判断、颜色和阴影硬编码。
- [ ] 所有正式主题的深浅模式均可用；密度三档无裁切。
- [ ] 正常、悬停、焦点、选中、禁用、加载、空、错误、成功与危险状态齐全。
- [ ] 1440×900、1366×768 检查通过；200% 缩放时关键操作仍可访问，宽表格可滚动。
- [ ] 长域名、文件路径、中文/英文、数字、缺失图标/字体、背景图失败均有合理表现。
- [ ] 键盘焦点清晰；弹窗与菜单键盘行为保留；对比度按有效背景实测。
- [ ] 主题切换不丢终端连接、编辑内容、表单、当前路由和查询状态。
- [ ] 预览取消、应用保存、恢复默认、旧配置迁移、损坏配置回退行为正确。
- [ ] 减少动效与禁用透明可用；无持续装饰动画或明显布局跳动。
- [ ] 检查 Element Plus 挂载到 body 的菜单、弹窗、提示，避免遗漏主题作用域。
- [ ] 列表行使用 inset；下拉/对话框外壳使用 float；抽屉外壳使用 card；无页面专属背景色。Element Plus 至少覆盖：dropdown/select、autocomplete、cascader、日期时间面板、popover/tooltip 箭头、dialog/message-box、message/notification、drawer 头身脚，以及表格条纹、hover、当前行、展开区、固定列。
- [ ] 颜色只从一个解析结果写出；禁止 `applyAccentPalette` 与 resolved 变量各算一套且浅色修正不同步。
- [ ] `x-panel.theme` 与 `x-panel.appearance` 可导入导出；恶意/超大/可执行内容被拒绝。
- [ ] 自定义字体失败时回退系统栈；编辑器换主题不丢撤销栈。

配置解析、校验、迁移和覆盖优先级适合自动测试；预览取消和状态保留应有必要的行为测试；视觉使用展示页与样板页面截图核查。不能只凭编译通过宣布 UI 验收完成。

## 13. 长期维护要求

新增能力按“归属 → 模板 → 语义样式/变体 → 全状态 → 主题验证”的顺序开发。新增主题字段同时更新字段契约、默认值、校验、迁移与展示页。新增变体需解释现有变体为何不足，避免同义重复。

规范版本变更记录行为或契约变化；主题内容版本记录视觉调整。破坏性配置变化必须给迁移方案。文档与实现冲突时记录差异并修正，不能默默形成另一套规则。

当前不需要再确认的决策：主题是完整预设、深浅同等完善、细粒度能力通过 overlay 表达、公共模板、渐进迁移、主题包与外观 overlay 两种文件、色板优先以保持和谐、自定义字体按受限二进制资源实现、文件契约与运行时类型分离、覆盖优先级与配方状态固定。

已确定的首批正式主题：`atelier`（工坊）与 `lumen`（流光）。圆角贯通、胶囊例外、终端外观共用等行为不得倒退。

## 14. 迁移期实现说明（不是 1.3 目标契约）

本节记录**当前代码**，避免把硬编码写进目标。新增主题**不必**修改 `ThemeId` 联合类型；那是迁移期债。目标见第 7 节。

实现目录：`frontend/src/theme/`。当前类型在 `types.ts`，当前注册表在 `catalog.ts`。

已知与 1.3 不符、仍待拆的债：

- 图表首色在无用户主色覆盖时走主题固定数组（有覆盖时分类首色已替换）
- 背景图仍走 JPEG data URL + localStorage（字体已用 IndexedDB，不再复用该存储）
- 存量业务页仍有 `el-fill-color-*` 等间接消费，未全部改成 inset/float 类名

本机存储键：`xp-appearance-v1`。旧 Pinia `global` 外观字段会迁移到该键。`AppearanceConfig` 仅作为备份；加载时本机 v1 优先，空的 `{}` 不会覆盖本机偏好。

落地顺序（规范要求，仍分阶段）：

1. 先锁文件契约、优先级、版本、缺失主题、资源规则，用两个内置主题验证能否表达  
2. 保证旧 appearance 导入 → 保存 → 再导出兼容，再接主题包安装；始终一个 resolver  
3. 集中生成全部最终颜色，统一四种配方和 Element Plus 映射；迁首页与代表性行组件  
4. 用 inset hover 强度、副色 hex、卡片顶边开关做扩展验收  
5. 字体资源生命周期与 Monaco 外观更新（不得走会 `setValue` 的内容加载）  
6. 两类导入导出、深浅展示页、状态保留验收后再逐模块推广

### 14.3 组件接入

页面只使用 `--xp-*` 语义变量和公共结构，不判断 `data-theme` 的具体名称。

```vue
<div class="page-header">
  <h3>{{ title }}</h3>
  <div class="header-actions"><slot name="actions" /></div>
</div>
```

布局壳：`Sidebar` / `Header` / `ModuleChrome` 读取 `html` 上的 `data-sidebar-variant`、`data-subnav-variant`、`data-card-variant`。对象详情使用 `.object-nav`。工作台路由设置 `meta.template = 'workbench'`。

圆角风格作用于侧栏选中项、顶栏主机名、Logo、图标底座、按钮、卡片和浮层。只有「胶囊」局部导航使用全圆；侧栏色块选中跟随 `--xp-radius-sm`，不再单独使用 `999px`。

开发展示页：`/dev/theme`（不进主导航）。
