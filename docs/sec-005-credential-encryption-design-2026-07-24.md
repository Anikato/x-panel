# X-Panel 敏感凭据加密与权限收紧设计

**日期：** 2026-07-24

**风险编号：** SEC-005

**状态：** 实现完成，待测试机升级验收

## 1. 目标

在不关闭 Fleet Center、节点、证书、备份和数据库管理功能的前提下，完成以下整改：

1. 复制 X-Panel SQLite 数据库本身不能直接恢复外部系统密码、Token 和私钥。
2. 当前最新版可以直接升级；首次启动自动生成独立密钥并迁移历史明文。
3. 普通数据库备份只包含密文，恢复时必须持有匹配的密钥环。
4. 安装、启动、升级和恢复流程统一收紧 X-Panel 自有文件权限。
5. 密文具有格式与密钥版本，能够轮换密钥并重新加密历史数据。

登录密码继续使用 bcrypt 单向哈希，不改为可逆加密。

## 2. 威胁模型与边界

本设计主要防护以下场景：

- SQLite 文件、普通数据库备份或磁盘快照被单独复制；
- 非服务账号读取权限配置过宽的 X-Panel 数据；
- 密文被跨字段替换、截断或篡改；
- 升级中断造成部分记录是明文、部分记录是密文；
- 恢复了数据库但遗漏密钥，应用把密文误当成真实凭据继续运行。

本设计不能防止已经取得 root 权限、能够同时读取进程内存、密钥环和数据库的攻击者。必须以最小文件权限、主机访问控制和备份隔离作为补充控制。

Nginx、HAProxy、GOST 等外部进程运行时必须读取的私钥或认证配置无法始终保持密文，这类生成文件使用 `0600` 或满足对应服务账号读取需求的最小权限。

## 3. 方案选择

采用显式仓储层加密，不使用 GORM 模型 Hook 或透明数据库加密：

- 当前仓储大量使用 `map[string]interface{}` 更新，模型 Hook 无法可靠覆盖；
- 部分迁移和业务逻辑直接访问 `global.DB`，必须显式识别和收口；
- SQLCipher 会改变构建与部署依赖，但仍不能提供字段上下文、密钥版本和按字段轮换；
- 显式仓储加密的调用路径可审计、可测试，失败语义清晰。

## 4. 密钥环

### 4.1 路径与权限

新增 `system.credential_key_path` 配置。安装器默认写入：

```text
<安装目录>/secrets/credential-keyring.json
```

旧配置缺少该字段时，根据 `system.data_dir` 的父目录推导相同默认位置。密钥目录必须是普通目录且权限为 `0700`，密钥环必须是普通文件且权限为 `0600`，不接受符号链接。

密钥环与 SQLite、`config.yaml` 和 JWT Secret 相互独立。不得从 `jwt_secret`、管理员密码、机器 ID 或其他低熵、可变化的数据派生 KEK。

### 4.2 格式

密钥环使用带版本的 JSON：

```json
{
  "version": 1,
  "activeKeyId": "kek-<随机标识>",
  "keys": {
    "kek-<随机标识>": "<32 字节随机密钥的 Base64>"
  }
}
```

- KEK 使用 `crypto/rand` 生成 256 bit 随机值。
- 首次创建使用排他创建和 `0600` 权限，写入后执行 `fsync`。
- 已有密钥环只加载和校验，不因升级而重新生成。
- 旧 KEK 在仍可能存在历史备份时保留；不得自动删除。

## 5. 信封加密格式

每个非空秘密独立生成一个 256 bit DEK：

1. DEK 使用 AES-256-GCM 加密业务明文。
2. 当前活动 KEK 使用 AES-256-GCM 包装 DEK。
3. 两层 GCM 分别使用独立的 96 bit 随机 Nonce。
4. 业务密文使用逻辑字段名作为 AAD，例如 `hosts.password`、`settings.FleetInstanceToken`，防止密文被移动到其他字段后仍能通过验证。

字段内编码格式：

```text
xpanel:enc:v1:<kek-id>:<wrapped-dek-base64url>:<ciphertext-base64url>
```

解密必须校验：

- 前缀和格式版本；
- KEK ID 是否存在；
- Base64、Nonce 和密文长度；
- KEK 包装层认证标签；
- 业务数据层认证标签和 AAD。

任何校验失败都返回错误，不得把无法解密的值作为明文回退使用。空字符串保持为空。

## 6. 敏感数据注册表

首轮必须覆盖以下 SQLite 字段：

| 表 | 字段 |
|---|---|
| `hosts` | `password`、`private_key`、`pass_phrase` |
| `nodes` | `token`、`ssh_password` |
| `backup_accounts` | `access_key`、`credential` |
| `database_servers` | `password` |
| `database_instances` | `password` |
| `acme_accounts` | `private_key`、`eab_hmac_key` |
| `dns_accounts` | `authorization` |
| `certificates` | `private_key` |
| `cert_sources` | `token` |
| `websites` | `basic_password` |
| `gost_services` | `auth_pass` |
| `gost_chains` | `hops` |
| `cronjobs` | `encrypt_password` |
| `ha_proxy_config_versions` | `content` |

`settings.value` 仅在 Key 属于以下集合时加密：

- `MFASecret`
- `GitHubToken`
- `AgentToken`
- `CertServerToken`
- `FleetInstanceToken`
- `FleetEnrollmentToken`
- `HAProxyStatsPass`
- `GostAPIPass`
- `ProxyAddress`
- `SecurityEntrance`

`Password` 是 bcrypt 哈希，不进入可逆加密集合。非秘密设置保持可读，避免把通用设置仓储变成不透明黑盒。

新增可恢复凭据字段时，必须同时更新注册表、仓储读写和迁移测试。

## 7. 仓储读写规则

- Create、Save 和 Update 在进入 GORM 前加密注册字段。
- Get、List 和 Page 在离开仓储前解密注册字段。
- `map` 更新仅转换注册字段，不改写其他业务值。
- 加密函数识别当前格式；已经使用活动 KEK 加密的值不重复加密。
- 业务 Service 始终接收明文，不直接解析密文格式。
- 数据迁移和确有必要的直接数据库访问必须调用同一加密组件，不能另写算法。
- API 模型中仍可被 JSON 序列化的密码、Token 和 Credential 同步改为不直接回显；更新接口继续使用“空值表示保持原秘密”的语义。

## 8. 首次升级与启动状态机

初始化顺序调整为：

1. 加载配置并收紧配置、数据目录和日志目录权限；
2. 打开 SQLite，收紧数据库、WAL 和 SHM 权限；
3. 执行结构迁移和默认数据初始化；
4. 检查密钥环与数据库凭据状态；
5. 执行凭据迁移；
6. 只有全部成功后才启动 Cron、节点心跳、Fleet Reporter 和 HTTP 服务。

状态处理如下：

| 密钥环 | 数据状态 | 行为 |
|---|---|---|
| 不存在 | 全部为空或明文 | 原子创建密钥环并执行首次迁移 |
| 存在 | 全部为空或明文 | 使用现有活动 KEK 迁移 |
| 存在 | 明文和密文混合 | 校验已有密文并幂等迁移剩余明文 |
| 存在 | 全部为合法密文 | 正常启动 |
| 不存在 | 存在任意密文 | 拒绝启动，提示恢复匹配密钥环 |
| 存在 | 密文损坏或 KEK ID 缺失 | 拒绝启动，提示密钥或数据库不匹配 |

首次迁移在单个数据库事务中执行。迁移前在 `0700` 的受控恢复目录创建 `0600` SQLite 快照；事务成功后立即删除临时明文快照。迁移失败时事务回滚并保留快照，日志只记录路径和错误类型，不记录任何字段值。

迁移标记只能在全部字段成功后写入。即使标记存在，启动时仍抽样或扫描验证不存在明文回退，避免人为修改或旧版本写回明文。

## 9. 升级、回滚与恢复

### 9.1 正常升级

在线安装器升级和面板内升级当前都只替换二进制，不删除安装目录中的密钥环。新版本启动时按状态机执行，已有密钥不得重建。

### 9.2 回滚旧二进制

新版本把字段迁移为密文后，旧二进制无法使用这些外部凭据。回滚必须恢复迁移失败时保留的明文快照，或在仍运行新二进制时通过受控恢复命令导出一次性 `0600` 旧格式数据库，然后再替换旧二进制。

不得采用同时长期保存明文列和密文列的双写方案。

### 9.3 数据库备份与恢复

- `xpctl backup db` 继续只备份 SQLite，备份内容中的注册字段保持密文。
- 同一主机恢复复用当前密钥环。
- 跨主机恢复必须先安全复制密钥环，再恢复数据库。
- 恢复前校验数据库完整性，并使用临时只读检查确认所有密文 KEK ID 都能在当前密钥环中解析；不匹配时不得替换当前数据库。
- `xpctl doctor` 只报告密钥环是否存在、权限是否安全、所需 KEK ID 是否齐全，不输出密钥或密文。

密钥环的离线副本由管理员通过受控介质单独保管，普通数据库备份命令不自动把密钥和数据库打包在一起。

## 10. 密钥轮换

轮换流程：

1. 生成新 KEK，安全写入密钥环但保留旧 KEK；
2. 将新 KEK 标记为活动密钥；
3. 在数据库事务中逐条解密并使用新 KEK 和新 DEK 重新加密；
4. 校验所有注册字段均使用活动 KEK；
5. 提交事务并记录不含秘密的审计结果。

轮换失败时旧 KEK 保留，因此旧密文仍可读取；不得在同一操作中删除旧 KEK。首轮提供后端轮换能力和自动化测试，管理入口必须复用现有管理员认证，不新增未认证控制通道。

## 11. 权限策略

安装器最早阶段设置 `umask 077`，systemd Unit 设置 `UMask=0077`。X-Panel 自有路径至少满足：

| 路径 | 权限 |
|---|---|
| 配置文件、SQLite、WAL、SHM、密钥环 | `0600` |
| secrets、db、log、备份及临时迁移目录 | `0700` |
| X-Panel 主程序和 `xpctl` | `0755` |
| 证书私钥及包含认证信息的生成配置 | `0600` |

启动时只修复 X-Panel 自有普通文件和目录。遇到符号链接、非预期文件类型或 `chmod` 失败时拒绝启动并给出具体路径，不递归修改用户指定的外部目录。

## 12. 错误处理与日志

- 错误只包含表名、字段名、记录 ID、KEK ID 和错误类别。
- 不记录明文、完整密文、DEK、KEK 或认证标签。
- 加密或解密失败不得被忽略。
- 读取列表时任一记录失败应使整个请求失败，避免返回部分可信数据。
- Fleet、Cron、证书同步和节点心跳必须在凭据迁移成功后启动。

## 13. 测试与验收

实施必须遵循 TDD，至少覆盖：

1. AES-GCM 信封加密往返、随机 Nonce、AAD 隔离和篡改拒绝。
2. 密钥环排他创建、权限、损坏格式、未知版本和未知 KEK。
3. 每个注册字段的 Create/Get/Update/List 加密与解密。
4. 敏感 Setting Key 加密，普通 Setting 和 bcrypt `Password` 保持原值。
5. 全明文、全密文、混合状态、幂等重启、迁移中断和事务回滚。
6. 已加密数据库缺少密钥、使用错误密钥或密文损坏时拒绝启动。
7. 当前最新版数据库升级后能够正常启动并使用原有凭据。
8. `xpctl backup db` 不出现秘密哨兵，正确密钥恢复成功，错误或缺失密钥恢复被拒绝。
9. 新安装、升级安装、数据库/WAL/SHM、配置、密钥和备份权限。
10. 密钥轮换后新旧数据可读、所有当前记录改用活动 KEK、旧备份仍可由保留的旧 KEK 解密。
11. HTTP 响应不直接回显已注册的密码、Token、私钥或 Credential。
12. 后端全量测试、race 检查和 `go vet` 不新增失败。

数据库秘密哨兵验收：在每类字段写入唯一秘密，完成业务读写、升级、备份和轮换后，直接扫描 SQLite、WAL、SHM、普通日志和操作日志，不得发现该明文。

## 14. 延期项

- TPM、云 KMS、系统 Keyring 和外部 Vault 适配器；
- 自动把密钥环上传到远程备份目标；
- 自动销毁仍被历史备份引用的旧 KEK；
- 加密用户任意写入且无法可靠判定是否包含秘密的所有自由文本字段。

这些延期项不影响独立密钥文件方案保护当前已识别的可恢复凭据。
